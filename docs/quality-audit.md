# TY Music 工程质量审查（2026-11-18）

审查基线：`e10937731549166565c1ee3d7fd5b2318b5a85c7`。本次仅增加审查记录，不修改运行逻辑，不把下列方案记作已修复、已合并或已部署。

## 结论与范围

目前有合适的局部设计和自动验证，但仍有已复现的资料恢复、播放竞态、传输释放及无效绘制问题，尚不符合全链路高标准。问题集中在跨入口状态没有统一所有者，以及旧传输路径缺少完整生命周期；文件长度本身不是重构理由。

本次读取播放／本地曲库／收藏／队列、双源搜索及其直接依赖、Node／Workers 请求、场景与绘制生命周期、静态分发、构建和 CI。重点沿近期搜索、动效与迁移改动追踪。未逐行认证所有旧页面、Rust 桌面代码、第三方依赖安全和许可，也未重做全站浏览器验收。

应保留的基础：

- `search-session.js` 集中维护网易云先显示、Embeat 异步补充、分页、取消与旧响应隔离。
- `gd-embeat-core.js` 在浏览器与服务端复用协议；Embeat 传输已有截止时间、大小限制及来源身份检查。
- `src/Scene.jsx`、`src/sceneStore.mjs`、`src/renderLoop.mjs` 已处理页面、隐藏、离屏和卸载；局部网格已能静止停帧。
- Pages 白名单发布、路径／符号链接校验、内容哈希分块与真实 Workers runtime 检查已存在。

## 发现

P1 表示本项目内优先修复的数据可见性、播放正确性或请求无法结束问题；P2 表示后续可靠性、资源或维护问题。以下“复现”均使用基线真实函数及受控输入，不代表已在用户个人曲库或线上触发。

### F1 · P1 · 收藏引用的歌曲元数据会被裁掉（已复现）

位置：`player.js:314` 保存歌曲缓存，`player.js:2499` 恢复收藏。

收藏只持久保存 ID；歌曲元数据保存时转为对象，并裁到最后 500 项，未保护收藏／歌单引用。收藏 `1`，缓存 `1…501` 后执行实际 `saveAll()`：收藏 ID 仍在，元数据被删，重新加载收藏时被跳过。数字对象键还按数值枚举，不能代表最近访问顺序。

影响：收藏条目刷新后不再显示；这不是收藏 ID 被删除，也不证明历史缺失的元数据能自动恢复。歌单引用同一缓存，应一并验证。

最小改法：把用户资料引用的必要元数据与可淘汰的浏览缓存分开管理，兼容旧存储。超额／写入失败明确反馈，不能静默抛弃用户引用。**不得清空现有资料处理兼容。**

验收：超过 500 首、混合数字与 Embeat ID、收藏和歌单引用、刷新往返、旧资料加载及存储额度不足；被引用的已有元数据完整保留。

### F2 · P1 · 远端响应可覆盖刚选中的本地歌曲（已复现）

位置：`player.js:965` 远端选择代次，`player.js:1158` 远端返回应用，`player.js:4049` 本地播放入口。

远端入口的取消／代次保护不覆盖本地入口。远端 A 解析未完成时选本地 L，随后 A 返回，在本地处于开头或暂停等条件下可替换 `audio.src`，而 `currentTrack` 仍为 L。

影响：声音与界面不一致。远端→远端已有保护，应复用其原则。

最小改法：本地与远端共用播放选择代次和资源所有权，来源解析保留各自 adapter；旧解析、播放成功／失败回调不能更新新的选择。

验收：远端→本地、本地→远端、本地→本地、同曲重复选择和延迟失败；最后一次选择同时决定音频、标题、歌词与播放状态，保留 Safari 用户手势内启动路径。

### F3 · P2 · 本地 Blob URL 未完整释放（已复现）

位置：`player.js:3934` 元数据探测，`player.js:4065` 播放 URL。

探测成功与失败都未撤销创建的 URL；返回的 `objectURL` 不被上传保存路径使用。播放 URL 仅在结束时释放，提前切歌替换回调会遗留前一首 URL。本地 L→M→M 结束，两个播放 URL 只释放一个。

影响：连续导入和切歌可能保留音频 Blob；本次未测真实浏览器内存或温升，不能将模拟计数换算为发热幅度。

最小改法：探测完成即释放；播放生命周期拥有当前 URL，在替换、失败、结束时释放，并保护正在使用的新 URL。

验收：成功／失败探测、提前切歌、删除当前本地歌曲和播放失败的创建／撤销计数；浏览器连续导入切歌后检查资源是否回落。

### F4 · P2 · 随机播放使用被替换前的队列（已复现）

位置：`player.js:1466` 下一首，`player.js:2588`、`4337`、`4561` 等队列替换入口。

随机顺序只在开启时生成，页面替换播放队列未同步；开启随机也未按当前歌曲重定位。随机 `[A,B,C]` 改播 `[X,Y]` 后，下一首仍可选到 B。

最小改法：队列替换、当前身份与随机顺序由同一个 module 维护，页面使用同一 interface；不额外建设通用状态框架。

验收：专辑／收藏／本地队列切换、开关随机、队列面板点播、上一首／下一首；不越出当前有效队列。

### F5 · P1 · 旧 JSON 传输中断后可一直 pending（已复现）

位置：`server-simple.js:90` `_httpsGetJSONOnce`，`server-simple.js:113` 响应处理，`server-simple.js:221` 去重调用。

响应只处理 `data/end`，缺少响应 `aborted/error` 的完整收尾。临时上游发出部分 JSON 后断开，50ms 配置超时下等待约 204ms 仍未结束。现有 socket 超时不是覆盖整个操作的绝对截止时间。

影响：专辑、歌手、歌词等调用可能挂起；Node 的共享 `pendingRequests` 也可能保留同 URL 的挂起 Promise。Workers 已关闭跨请求共享 I/O，不可为重构恢复该行为。

最小改法：有界的上游请求 module 统一响应生命周期、绝对截止时间、大小上限和有限重定向；调用方保留领域格式校验。

验收：截断 JSON 立即失败且同 URL 下次可恢复；响应头停顿、慢流、相对重定向、循环、取消都有确定结果，响应和连接释放。

### F6 · P1 · 网易云封面失去全程超时和大小保护（已复现）

位置：`server-simple.js:175` `smartGet`，`server-simple.js:208` 连接后取消超时，`server-simple.js:1387` 累积封面 body。

连接成功后取消超时；读取完整图片时没有额外截止时间或大小限制。临时上游接通后不发响应，50ms 配置超时下等待约 203ms 仍挂起。

影响：上游停顿占住请求，大 body 可能增加内存压力；未测生产内存耗尽。音频流与完整封面下载的期限需求不同，不能给长音频生硬套用图片截止时间。

最小改法：完整封面下载使用覆盖响应头和 body 的总截止时间及 8MiB 上限，复用已有 Embeat 封面约束；独立核对音频流取消与 Range。

验收：头部停顿、body 停顿、持续慢流、超限响应按时终止；正常图片与音频 Range 不回归。

### F7 · P2 · API 缓存没有容量上限（已复现）

位置：`server-simple.js:62` `cacheSet`。

超过 500 条只删除过期项，未过期项全部保留，每次写入还扫描整个 Map。执行当前实现插入 5,000 个未过期键，最终仍有 5,000 条。

最小改法：硬性条目上限、明确的最旧项淘汰和过期语义；避免每次全量扫描。条目上限不等于字节上限，较大缓存值应结合传输／领域大小限制评估。

验收：超过容量仍有界，命中、过期、更新和淘汰稳定；不跨 Worker 请求共享进行中 I/O。未观测到生产 OOM，不据此给出内存收益百分比。

### F8 · P2 · 上游错误会被当作成功资源（代码确认，未在线上触发）

位置：`server-simple.js:1392` 网易云封面；`server-simple.js:723` 网易云歌词。

封面不检查状态和图片类型，非空 403／500 HTML 可返回 200 并标记缓存一周。歌词错误 JSON 可被转换为空歌词并缓存一小时；传输异常也被返回为空歌词，但该异常返回本身未写入上述缓存。

最小改法：成功状态、图片类型、非空有界 body 和歌词数据形状均通过后才缓存。合法无歌词与传输／协议失败分开，失败沿既有错误路径报告。

验收：403 HTML、500 JSON、非法图片类型、空图片、错误歌词对象不进入成功缓存；合法无歌词保持成功，上游恢复后立即可重试。

### F9 · P2 · Cover Flow 静止后继续逐帧写 DOM（已复现调度行为）

位置：`player.js:5316` `cfRender`，`player.js:5397` `cfLoop`。

弹簧已收敛、没有拖动时仍无条件预约下一帧；每帧遍历全部专辑，对可见卡片查询脊元素并设置样式。页面离开／改网格会调用 `cfStop`，因此不是所有页面永久运行，也不是已证明的隐藏标签高负载。

直接执行真实函数、100 张专辑、600 个模拟可见帧、初始静止：600 次渲染、166,200 次 style setter 调用、6,600 次脊元素查询，仍留一个待执行帧。此计数不等于浏览器实际重绘次数、CPU 耗时或温升。

最小改法：保留现有弹簧和几何，收敛后停帧，指针／键盘／尺寸／数据变化再唤醒；缓存节点引用，只更新变化范围。复用既有按需调度经验，不新增动画库。

验收：收敛后不留 RAF；拖动、惯性、快速切换、重复进入和 resize 能唤醒；隐藏／离开停止。真实页面核对视觉与点击，再在相同负载下测 CPU／帧时间，不能仅凭单元计数宣称不发热。

### F10 · P2 · 发布和页面契约分散（维护风险与验证缺口）

位置：`static-files.cjs:10`、`scripts/build-pages.mjs:18`、`desktop/build.mjs:10`、`service-worker.js:11`；`src/mount.jsx:250`、`src/sceneStore.mjs`、`scripts/verify-scenes.mjs:66`；`.github/workflows/`。

公开文件清单在多处手工重复，新增运行脚本需同步各处。桌面准备只复制现有 bundle，缺失单文件静默跳过；桌面 CI 的 paths 没有覆盖 `browser-provider.js`、`search-session.js`、`gd-embeat-core.js` 等实际复制输入，单独修改这些输入不会触发 main 的 push 桌面构建。这是具体流程风险，不代表当前安装包已证实缺文件。

流派消失回归说明 HTML 宿主页、挂载配置与场景声明可漂移。当前测试执行实际 JSX 并检查 12 个分类，但 HTML 宿主归属仍由测试假设提供。Web CI 有 900,000 字节初始模块预算和真实 Workers smoke，尚无真实浏览器导航／完整主要流程与帧时间门禁；本次初始模块图为 558,251 字节（4 个文件），不是网页全部 JS 或传输字节。

最小改法：一处维护公开资源事实，按 Node／Pages／桌面／离线需求派生并校验差异；必要文件缺失即失败。对实际 HTML 核对宿主归属；补齐构建输入触发范围，桌面打包前保证源码与 bundle 同步。复用现有测试，按当前工具支持建立真实浏览器验收，不擅自引入其他浏览器驱动。

验收：缺运行脚本构建失败、私有文件仍不发布、模块图完整；从真实 HTML 发现错绑；首页 12 个分类、搜索、播放／歌词、收藏和本地音乐不缺失。性能门槛先用同一设备／窗口／负载建立基线再确定，不任意承诺 60fps。
